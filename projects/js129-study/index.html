this Binding Checklist

  1. Locate the exact this.
  2. Ask what function body directly contains that this.
  3. Is that function regular or arrow?
  4. If regular: how is that exact function invoked?
  5. If arrow: what surrounding function/scope does it capture this from?
  6. Then decide what this.name is, or whether it throws.

Strict mode plain call

'use strict';

let bark = dog.bark;
bark(); // plain function call; this = undefined; TypeError

Bound function

let bark = dog.bark.bind(dog);
bark.call({ name: 'Maya' }); // still uses dog; bind cannot be overridden
Say “arrow captures this,” not “arrow is bound,” unless .bind() is literally used.

Constructor Functions and new

'use strict';

function Dog(name) {
  this.name = name;
}

Dog.prototype.bark = function() {
  console.log(`${this.name} barks.`);
};

let dog = new Dog('Rex');

new Dog('Rex') does roughly four things:

  1. Creates a new object.
  2. Sets that object’s prototype to Dog.prototype.
  3. Calls Dog with this set to the new object.
  4. Returns the new object.
this.name = name creates an own property on the instance. Dog.prototype.bark creates shared behavior on the prototype.

Prototype Lookup and Shadowing

dog = {
  name: "Rex"
  // [[Prototype]] → Dog.prototype
}

Dog.prototype = {
  constructor: Dog,
  bark: function() {}
}

Lookup starts on the object, then walks up the prototype chain.

dog.bark = function() {
  console.log(`${this.name} yips.`);
};

dog.bark(); // own method shadows prototype method
Own properties are checked before prototype properties. Shadowing does not delete the prototype method. 
delete dog.bark;
dog.bark(); // prototype method is visible again

The constructor Property

Dog is a function object. The default prototype has a property that points back to that function.

function Dog(name) {
  this.name = name;
}

Dog.prototype.constructor === Dog; // true
constructor is mostly just a property lookup. It is not magic proof of what created the object.

Replacing the prototype loses the default constructor property

Dog.prototype = {
  bark: function() {}
};

let dog = new Dog('Rex');

dog.constructor === Dog;    // false
dog.constructor === Object; // true

Restore it manually

Dog.prototype = {
  constructor: Dog,
  bark: function() {}
};

Pseudo-Classical Inheritance

function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function() {
  console.log(`${this.name} makes a noise.`);
};

function Dog(name, breed) {
  Animal.call(this, name);
  this.breed = breed;
}

Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

Dog.prototype.bark = function() {
  console.log(`${this.name} barks.`);
};

Animal.call(this, name)

Borrow the parent constructor to initialize name on the current dog instance.

Object.create

Creates a new object that delegates to Animal.prototype.

Prototype chain

dog → Dog.prototype → Animal.prototype → Object.prototype

instanceof

Checks whether a constructor’s prototype appears in the object’s prototype chain.

Classes, extends, and super

class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    console.log(`${this.name} makes a noise.`);
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }

  speak() {
    super.speak();
    console.log(`${this.name} barks loudly.`);
  }
}

super(name) calls the parent constructor. super.speak() calls the parent method but keeps the current this.

Class methods are placed on prototypes. They are not copied onto each instance and are not automatically bound.

Static Methods, Private Fields, and Getters

Static methods

class Dog {
  bark() {}

  static describe() {
    console.log('Dogs are loyal animals.');
  }
}

Dog.describe(); // works
dog.describe(); // TypeError

Static methods live on the class/constructor itself, not on the prototype.

Private fields and getters

class Dog {
  #name;

  constructor(name) {
    this.#name = name;
  }

  get name() {
    return this.#name;
  }
}

dog.name; // calls getter
dog.hasOwnProperty('name'); // false
#name is private state. name is a getter on the prototype, not an own public data property.

Mixins and Factory Functions

Mixin pattern

const Swimmable = {
  swim() {
    console.log(`${this.name} swims.`);
  }
};

Object.assign(Dog.prototype, Swimmable);

This copies swim onto Dog.prototype. Instances use it through prototype lookup.

Factory function

function createDog(name) {
  return {
    name,
    bark() {
      console.log(`${this.name} barks.`);
    }
  };
}

let dog1 = createDog('Rex');
let dog2 = createDog('Maya');

dog1.bark === dog2.bark; // false
dog1 instanceof createDog; // false
dog1.hasOwnProperty('bark'); // true
A factory returns an object directly. It does not use new, and the returned object does not delegate to createDog.prototype.

Assessment Phrases to Memorize

  • “The call site is dog.bark(), so this is dog.”
  • “The function is extracted, so the original receiver is lost.”
  • “In strict mode, a plain function call has this set to undefined.”
  • “Own properties are checked before prototype properties.”
  • “This shadows the prototype method; it does not delete it.”
  • “The method is found on the prototype, but this is still determined by the call site.”
  • “Dog is a function object being used as a constructor.”
  • “Dog.prototype.constructor is a property that points back to the Dog function.”
  • “Replacing the prototype object loses the default constructor property.”
  • “Object.create(Animal.prototype) creates a new object that delegates to Animal.prototype.”
  • “Animal.call(this, name) borrows the parent constructor to initialize state on the current instance.”
  • “super.method() calls the parent method but keeps the current this.”
  • “Static methods live on the class/constructor itself, not on the prototype.”
  • “Factory functions return objects directly and do not use new.”
