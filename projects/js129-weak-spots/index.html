How to use this page

This page is not a full JS129 guide. It only covers the weak spots from the last mock session.

Main question to ask: where exactly does this property live? Instance, prototype, constructor/class function, or farther up the prototype chain?

1. The constructor property

The default constructor property lives on the prototype object and points back to the constructor function.

'use strict';

function Dog(name) {
  this.name = name;
}

console.log(Dog.prototype.hasOwnProperty('constructor')); // true
console.log(Dog.prototype.constructor === Dog);           // true

let dog = new Dog('Rex');

console.log(dog.hasOwnProperty('constructor')); // false
console.log(dog.constructor === Dog);           // true
Correct wording: Dog.prototype owns a property named constructor, and that property points back to the Dog function.
Do not say the instance directly points back to the constructor. The instance finds constructor through prototype lookup.

2. Replacing prototypes and losing constructor

When you replace Dog.prototype with a new object literal, you lose the original default constructor property.

'use strict';

function Dog(name) {
  this.name = name;
}

Dog.prototype = {
  bark() {
    console.log(`${this.name} barks.`);
  }
};

let dog = new Dog('Rex');

console.log(dog.constructor === Dog);    // false
console.log(dog.constructor === Object); // true
console.log(Dog.prototype.hasOwnProperty('constructor')); // false

The lookup is:

dog
  → Dog.prototype        // no constructor here
    → Object.prototype   // constructor is found here, points to Object
The chain is dog → Dog.prototype → Object.prototype, not dog → Dog → Object.

Restore it manually

Dog.prototype = {
  constructor: Dog,

  bark() {
    console.log(`${this.name} barks.`);
  }
};

3. Object.create inheritance

Object.create(Animal.prototype) creates a new object whose prototype is Animal.prototype.

'use strict';

function Animal(name) {
  this.name = name;
}

function Dog(name) {
  Animal.call(this, name);
}

Dog.prototype = Object.create(Animal.prototype);

let dog = new Dog('Rex');

console.log(dog.constructor === Dog);    // false
console.log(dog.constructor === Animal); // true
console.log(dog instanceof Dog);         // true
console.log(dog instanceof Animal);      // true

Because Dog.prototype.constructor = Dog was not restored, dog.constructor climbs to Animal.prototype.constructor.

dog
  → Dog.prototype
    → Animal.prototype   // constructor found here, points to Animal
      → Object.prototype

Correct setup

Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

4. constructor vs instanceof

dog.constructor

Property lookup. It asks where the property named constructor is found.

dog instanceof Dog

Prototype-chain check. It asks whether Dog.prototype appears in the object's prototype chain.

Dog.prototype = Object.create(Animal.prototype);

let dog = new Dog('Rex');

dog.constructor === Animal; // true, property lookup
dog instanceof Dog;         // true, Dog.prototype is in the chain
These can disagree. constructor is not the same thing as instanceof.

5. hasOwnProperty locations

hasOwnProperty checks only the object you call it on. It does not search the prototype chain.

dog.hasOwnProperty('x')
// Does the instance itself own x?

Dog.prototype.hasOwnProperty('x')
// Does the prototype object itself own x?

Dog.hasOwnProperty('x')
// Does the constructor/class function itself own x?
'use strict';

class Dog {
  constructor(name) {
    this.name = name;
  }

  bark() {
    console.log(`${this.name} barks.`);
  }

  static describe() {
    console.log('Dogs are loyal.');
  }
}

let dog = new Dog('Rex');

console.log(dog.hasOwnProperty('name'));           // true
console.log(dog.hasOwnProperty('bark'));           // false
console.log(Dog.prototype.hasOwnProperty('bark')); // true
console.log(Dog.hasOwnProperty('describe'));       // true
A method is still a property. It is a property whose value is a function.

6. Static methods

Static methods live directly on the class/constructor function, not on the prototype.

'use strict';

class Dog {
  bark() {
    console.log('woof');
  }

  static describe() {
    console.log('Dogs are loyal.');
  }
}

let dog = new Dog();

console.log(Dog.prototype.hasOwnProperty('bark')); // true
console.log(Dog.hasOwnProperty('describe'));       // true

Dog.describe(); // works
dog.describe(); // TypeError
Assessment phrase: describe is static, so it lives directly on Dog. Instances do not access it through their normal prototype chain.

7. Private fields and getters

#name is private state. It is not a normal public own property called name.

'use strict';

class Dog {
  #name;

  constructor(name) {
    this.#name = name;
  }

  get name() {
    return this.#name;
  }

  rename(newName) {
    this.#name = newName;
  }
}

let dog = new Dog('Rex');

console.log(dog.name);                    // Rex
console.log(dog.hasOwnProperty('name'));  // false

dog.rename('Maya');
console.log(dog.name);                    // Maya

console.log(dog.hasOwnProperty('rename'));           // false
console.log(Dog.prototype.hasOwnProperty('rename')); // true
dog.name works because it invokes a getter. But name is not an own public property on the instance.

8. Factory functions and instanceof

A factory function returns an object directly. It does not create an instance through new.

'use strict';

function createDog(name) {
  return {
    name,

    bark() {
      console.log(`${this.name} barks.`);
    }
  };
}

let dog1 = createDog('Rex');
let dog2 = createDog('Maya');

console.log(dog1.bark === dog2.bark); // false
console.log(dog1.hasOwnProperty('bark')); // true
console.log(dog1 instanceof createDog); // false
dog1 instanceof createDog is false because createDog.prototype is not in dog1's prototype chain.

9. super basics

super.method() starts lookup one level above the current class's prototype and calls the first matching method it finds.

Normal parent method call

'use strict';

class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    console.log(`${this.name} makes a noise.`);
  }
}

class Dog extends Animal {
  speak() {
    super.speak();
    console.log(`${this.name} barks.`);
  }
}

let dog = new Dog('Rex');
dog.speak();

// Rex makes a noise.
// Rex barks.
super.speak() calls the parent method, but keeps the current this.

super does not fix lost this

let speak = dog.speak;
speak(); // TypeError

If the method is extracted and called plainly, this is undefined in strict mode. super can find the parent method, but it does not repair the lost receiver.

Explicit this with .call

class Dog extends Animal {
  speak() {
    super.speak.call({ name: 'Maya' });
  }
}

new Dog('Rex').speak(); // Maya makes a noise.

Practice drills

Answer out loud first, then reveal the solution.

Drill 1: default constructor property 
'use strict';

function Dog(name) {
  this.name = name;
}

let dog = new Dog('Rex');

console.log(Dog.prototype.hasOwnProperty('constructor'));
console.log(dog.hasOwnProperty('constructor'));
console.log(dog.constructor === Dog);
Output: true, false, true. The prototype owns constructor; the instance finds it through lookup.
Drill 2: replaced prototype 
'use strict';

function Dog(name) {
  this.name = name;
}

Dog.prototype = {
  bark() {
    console.log(`${this.name} barks.`);
  }
};

let dog = new Dog('Rex');

console.log(dog.constructor === Dog);
console.log(dog.constructor === Object);
Output: false, true. The new prototype object lacks constructor, so lookup reaches Object.prototype.constructor.
Drill 3: Object.create without constructor restoration 
'use strict';

function Animal() {}
function Dog() {}

Dog.prototype = Object.create(Animal.prototype);

let dog = new Dog();

console.log(dog.constructor === Dog);
console.log(dog.constructor === Animal);
console.log(dog instanceof Dog);
console.log(dog instanceof Animal);
Output: false, true, true, true. constructor is found on Animal.prototype, but both prototypes are in the chain.
Drill 4: static vs prototype 
'use strict';

class Dog {
  bark() {}
  static describe() {}
}

let dog = new Dog();

console.log(dog.hasOwnProperty('bark'));
console.log(Dog.prototype.hasOwnProperty('bark'));
console.log(Dog.hasOwnProperty('describe'));
console.log(dog.describe);
Output: false, true, true, undefined. bark is on the prototype; describe is on the class itself.
Drill 5: private field and getter 
'use strict';

class Dog {
  #name;

  constructor(name) {
    this.#name = name;
  }

  get name() {
    return this.#name;
  }
}

let dog = new Dog('Rex');

console.log(dog.name);
console.log(dog.hasOwnProperty('name'));
console.log(Dog.prototype.hasOwnProperty('name'));
Output: Rex, false, true. name is a getter on the prototype, not an own public property.
Drill 6: factory function 
'use strict';

function createDog(name) {
  return {
    name,
    bark() {}
  };
}

let dog = createDog('Rex');

console.log(dog.hasOwnProperty('bark'));
console.log(dog instanceof createDog);
Output: true, false. The object is returned directly by a factory. It is not linked to createDog.prototype.
Drill 7: super keeps current this 
'use strict';

class Animal {
  speak() {
    console.log(this.name);
  }
}

class Dog extends Animal {
  constructor(name) {
    super();
    this.name = name;
  }

  speak() {
    super.speak();
  }
}

new Dog('Rex').speak();
Output: Rex. super.speak() calls the parent method with the current dog instance as this.

Assessment phrases to memorize

“Dog.prototype owns a constructor property, and that property points back to the Dog function.”
“The instance does not own constructor; it finds it through prototype lookup.”
“Replacing the prototype object loses the default constructor property.”
“constructor is property lookup, while instanceof checks the prototype chain.”
“hasOwnProperty checks only the specific object it is called on.”
“Static methods live directly on the class/constructor function, not on the prototype.”
“A getter can make dog.name work even when name is not an own property.”
“A factory function returns an object directly, so the result is not automatically an instance of the factory.”
“super.method() calls the parent method while keeping the current this.”
“super can find the parent method, but it does not fix a lost this.”
